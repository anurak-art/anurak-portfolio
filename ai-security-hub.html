Module 01

AI Fundamentals

แนวคิดหลักที่ต้องเข้าใจก่อนพูดเรื่อง AI Security — ภาษาที่ใช้ร่วมกันระหว่างทีม Data/AI และทีม Security

01

Machine Learning vs Deep Learning

ML คือการให้ระบบ "เรียนรู้จากข้อมูล" แทนการเขียนกฎตายตัว ส่วน Deep Learning เป็นสาขาย่อยที่ใช้ Neural Network หลายชั้น (layers) เพื่อจับรูปแบบที่ซับซ้อน เช่น ภาพ เสียง และภาษา

Neural NetTraining Data
02

LLM (Large Language Model)

โมเดลภาษาขนาดใหญ่ที่ถูกฝึกด้วยข้อความปริมาณมหาศาล ทำนายคำถัดไปแบบ Transformer-based architecture จนสามารถสนทนา สรุป และให้เหตุผลได้

TransformerTokens
03

Generative AI

AI ที่สร้างเนื้อหาใหม่ (ข้อความ ภาพ โค้ด เสียง) แทนที่จะแค่จำแนกหรือทำนายค่า เป็นฐานของ Copilot, Chatbot และเครื่องมือสร้างสรรค์ต่างๆ

DiffusionGenAI
04

AI Agents & Agentic AI

ระบบที่ให้ LLM ตัดสินใจ วางแผน และเรียกใช้ "เครื่องมือ" (tools/API) ได้เอง — จุดที่ความเสี่ยงด้าน Security เพิ่มขึ้นมาก เพราะ Agent มีสิทธิ์กระทำการแทนมนุษย์

Tool-useAutonomy
05

RAG & Vector Database

Retrieval-Augmented Generation คือการดึงข้อมูลจาก Vector Database มาประกอบการตอบของ LLM ทำให้คำตอบอ้างอิงข้อมูลองค์กรได้แม่นยำขึ้น แต่ก็เปิดพื้นผิวโจมตีใหม่

EmbeddingsRetrieval
06

Prompt Engineering

ศาสตร์ของการออกแบบคำสั่ง (prompt) ให้โมเดลตอบสนองตามต้องการ — เป็นทั้งเครื่องมือเพิ่มประสิทธิภาพ และช่องโหว่ถ้าไม่มีการควบคุม (Prompt Injection)

System PromptContext
Module 02 — Governance & Standards

Framework การกำกับดูแล AI

มุมมองระดับ Governance ที่ผู้บริหารและ Compliance ต้องใช้อ้างอิง ก่อนลงรายละเอียดเชิงเทคนิค

NIST AI Risk Management Framework — 4 หน้าที่หลัก (Core Functions):

Govern

วางโครงสร้างกำกับดูแล

กำหนดนโยบาย บทบาทหน้าที่ และวัฒนธรรมองค์กรเพื่อบริหารความเสี่ยงของ AI อย่างต่อเนื่อง

Map

ระบุบริบทและความเสี่ยง

ทำความเข้าใจระบบ AI ข้อมูล และผู้มีส่วนได้ส่วนเสีย เพื่อระบุความเสี่ยงตั้งแต่ต้นทาง

Measure

วัดผลและทดสอบ

วิเคราะห์ ทดสอบ และติดตามตัวชี้วัดความเสี่ยงของระบบ AI อย่างสม่ำเสมอ

Manage

บริหารจัดการความเสี่ยง

จัดสรรทรัพยากรเพื่อลดความเสี่ยงที่ระบุไว้ และตอบสนองต่อเหตุการณ์ที่เกิดขึ้นจริง

ISO/IEC 42001 AIMS

มาตรฐานสากลฉบับแรกสำหรับ "ระบบบริหารจัดการ AI" (AI Management System) แนวคิดคล้าย ISO/IEC 27001 แต่ครอบคลุมวงจรชีวิตของ AI ตั้งแต่ออกแบบ พัฒนา จนถึงเลิกใช้งาน เหมาะสำหรับองค์กรที่ต้องการ certify ความพร้อมด้าน AI Governance

EU AI Act Risk-based

กฎหมายที่จัดระดับความเสี่ยงของระบบ AI เป็นชั้น และกำหนดข้อบังคับตามระดับความเสี่ยงนั้น

Unacceptable — ห้ามใช้ High Risk — ควบคุมเข้ม Limited — ต้องแจ้งผู้ใช้ Minimal — ไม่บังคับ

MITRE ATLAS — ลำดับขั้นการโจมตีระบบ AI (แนวคิดคล้าย Kill Chain):

01
Reconnaissance

สำรวจโมเดล API และ pipeline ที่เป็นเป้าหมาย

02
ML Supply Chain Compromise

แทรกแซง dataset, model registry หรือ dependency

03
ML Model Access

เข้าถึงโมเดลผ่าน API, endpoint ที่เปิดเผยเกินจำเป็น

04
ML Attack Staging

ทดสอบ craft input เพื่อหาวิธี bypass guardrail

05
Exfiltration

ดึงข้อมูลลับ, training data หรือ model weights ออกไป

06
Impact

ทำให้ระบบให้ผลลัพธ์ผิดพลาด หรือหยุดให้บริการ

Module 04 — Enterprise Control Mapping

จาก Enterprise Security Stack สู่ AI Security

โครงสร้างพื้นฐานด้าน Security ที่มีอยู่แล้ว (PKI, PAM, IAM, WAF, API Gateway) นำมาปรับใช้ป้องกันระบบ AI ได้ตาม NIST AI RMF

RMF Function
Enterprise Control
การประยุกต์ใช้กับ AI
Govern
PAM / IAM
ควบคุมสิทธิ์ของ AI Agent และ Service Account ที่เรียกใช้ API ภายใน ให้เป็นไปตามหลัก least privilege เหมือนบัญชี privileged ทั่วไป
Map
API Gateway
ทำ Discovery และจัดทำ Inventory ของ LLM endpoint / Agent tool-call ทั้งหมดในองค์กร เพื่อรู้ว่ามี attack surface ตรงไหนบ้าง
Measure
WAF / API Security
ตรวจจับ Prompt Injection และ Unbounded Consumption ผ่านการวิเคราะห์ traffic pattern และ rate-based rule ที่ layer หน้า LLM endpoint
Manage
PKI / Certificate Lifecycle Management
ทำ mTLS และหมุนเวียน certificate/secret ระหว่าง microservice ของ AI pipeline โดยอัตโนมัติ ลดความเสี่ยงจาก credential รั่วไหลหรือหมดอายุ
